📦 AREXX — Déploiement

Mettre en place le "sender" (celui qui parle au dongle USB TL-500/BS500) sur une machine distincte de celle-ci.

1. Éditer data/arexx/drivers/target.txt

Ce dossier drivers/ est généré automatiquement au démarrage de l'application (accessible directement sur cette machine, y compris sous Docker — c'est un volume monté, contrairement au code de l'application lui-même). Il contient le script d'installation et ses deux dépendances, déjà prêts.

target.txt contient une seule ligne (host:port) : l'adresse de ce récepteur, telle que joignable depuis la machine cible. Le port est déjà renseigné d'après la configuration actuelle — seul l'hôte reste à indiquer (l'application ne peut pas deviner de façon fiable sa propre adresse IP réseau) : 

A_REMPLACER:…

Remplacer A_REMPLACER par l'adresse IP réellement joignable depuis la machine cible, et écrire le résultat dans data/arexx/drivers/target.txt (fichier texte simple, éditable directement).

2. Copier tout le dossier data/arexx/drivers/ sur la machine cible

Une seule copie, en une fois — target.txt une fois édité (étape 1) voyage avec le reste :

scp -r data/arexx/drivers <utilisateur>@<machine cible>:/root/arexx-drivers
  • scripts/deploy-sender.sh — le script d'installation, à lancer une fois copié
  • rf_usb_http_rpi_0_6/ — utilisé si la machine cible est un Raspberry Pi 32 bits (ARMv6/ARMv7)
  • tl-500/ — sources compilées sur place pour toute autre architecture (64 bits, x86_64...)
  • target.txt — l'adresse éditée à l'étape 1

Le script détecte lui-même l'architecture (uname -m) et choisit le bon des deux — rien à choisir à la main.

3. Lancer le script (en root) sur la machine cible

Sans argument — l'adresse est lue directement dans target.txt :

./arexx-drivers/scripts/deploy-sender.sh

4. Ce que fait le script

  • Installe les dépendances système manquantes (libusb-1.0-0, et pour tl-500 : gcc/make/libusb-1.0-0-dev)
  • Copie/compile le bon programme, génère sa configuration (rulefile.txt ou url.txt) avec l'adresse lue dans target.txt
  • Installe et démarre un service systemd (arexx-sender.service) — persistant, redémarre au boot

Ré-exécutable sans risque (idempotent) — relancer le script met simplement à jour l'installation existante.

Vérification une fois lancé : systemctl status arexx-sender.service / journalctl -u arexx-sender.service -f
